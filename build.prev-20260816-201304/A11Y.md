# Accessibility review — build/poem.html

Reviewed against WCAG 2.2 AA. Static code read (no live browser render used —
findings below are computed/verified from source; flag if a visual re-check
is wanted).

## 1. Contrast (WCAG 1.4.3, AA) — PASS

Computed relative-luminance contrast ratios from the actual hex values in
`<style>`:

| Text | Color | Background | Ratio | Required | Result |
|---|---|---|---|---|---|
| Poem lines / signature | `#2b2620` | `#f7f4ee` | 13.3:1 | 4.5:1 | PASS |
| Credit line (0.75rem / ~12px) | `#6b6459` | `#f7f4ee` | 5.3:1 | 4.5:1 (small text) | PASS |

**Test to reproduce:** DevTools → inspect element → Accessibility pane shows
contrast ratio, or run `axe` on the rendered page (`axe.run()` in console) —
expect 0 contrast violations.

## 2. `prefers-reduced-motion` (WCAG 2.3.3, AAA / best practice) — PASS

`@media (prefers-reduced-motion: reduce)` sets `transition: none` and
`transform: none` on `.line, .signature, .credit`. Reveal becomes instant
(opacity flips with no animation) while the JS timer's 2000ms cadence is
untouched — matches contract §Accessibility notes exactly ("skip fade
transitions, keep timing").

**Test to reproduce:** Chrome DevTools → Rendering tab → "Emulate CSS
media feature prefers-reduced-motion: reduce" → reload → confirm lines
appear with no fade/slide, still one every ~2s (watch `console.log`
timestamps).

## 3. Color-alone distinction (WCAG 1.4.1) — PASS

Signature is distinguished by *italic + right-alignment + smaller size*,
not color alone.

## 4. Semantic markup — PASS

- `<html lang="en">` present.
- Single `<h1>` for the poem title.
- Poem lines as `<span class="line">` + `<br>` inside `<p class="stanza">`
  is an accepted accessible pattern for poetry (avoids fake list
  semantics); acceptable.

**Test to reproduce:** run the page through an accessibility tree
inspector (DevTools → Elements → Accessibility tab) — confirm heading
level 1 present, no empty/redundant landmarks.

## 5. Keyboard operability — PASS (trivially, N/A)

No interactive controls exist on the page (no buttons/links/inputs), so
there is nothing to tab to or activate. Nothing fails; nothing to test
beyond confirming no focusable dead zones — there are none.

## 6. WCAG 2.2.2 (Pause, Stop, Hide), Level A — EXEMPT (essential exception)

The reveal is auto-updating content that starts on load and runs for
~40s (20 lines × 2s), which would normally require a pause/stop/hide
mechanism under SC 2.2.2.

**Lead decision:** exempt under the "essential to the activity"
exception. The timed line-by-line reveal is the core activity of the
page, not decorative or incidental, and the mission's non-goals
explicitly rule out added controls (no replay/restart). No pause
control required. Recorded here for the record — no code change.

## 7. Minor note (not a WCAG failure)

Poem lines use `opacity:0` (per contract, to avoid layout shift), which
does **not** hide text from the accessibility tree — screen reader users
will hear/read the full poem immediately on load rather than
line-by-line. No WCAG success criterion mandates synchronized reveal for
assistive tech, so this is not a failure, just a note for awareness.
