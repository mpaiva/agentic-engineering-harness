# Accessibility acceptance checks — getting-started-page

Target: `build/artifacts/getting-started-page/index.html`
Tooling: Playwright (Chromium) + axe-core, run via a throwaway scratch script
(`/tmp/a11y-check/scan.mjs`, `/tmp/a11y-check/clean.mjs` — not part of the artifact).

## 1. Automated a11y scan — zero critical/serious violations (criterion 5)

Check: load the page under `file://`, inject `axe-core`, run `axe.run()`.

```
node /tmp/a11y-check/scan.mjs
```

Result: `VIOLATIONS: 0`.

Prior finding, now fixed: `scrollable-region-focusable` (serious) on each
`<pre>` command block (horizontally scrollable, not keyboard-reachable).
Fix: `tabindex="0"` added to every `<pre>` in `index.html`, plus a
`pre:focus-visible` outline rule in `style.css`.

## 2. Keyboard operability of copy buttons (criterion 4)

Check: `page.keyboard.press('Tab')` to reach a copy button, `Enter` to
activate it, confirm `navigator.clipboard.readText()` matches the button's
`data-command`.

```
node /tmp/a11y-check/clean.mjs
```

Result: first Tab stop lands on the (now-focusable) `<pre>`; `.copy-btn`
elements are native `<button type="button">`, natively Tab-reachable and
Enter/Space-activatable — no custom keydown handling needed. Scripted check:
focus first `.copy-btn`, press Enter → clipboard contains
`"git clone https://github.com/mpaiva/atomic-cockpit\ncd atomic-cockpit"`,
button text flips to "Copied". Confirmed.

## 3. Visible focus indicator (criterion 4)

Check: `style.css` — `a:focus-visible, button:focus-visible,
pre:focus-visible { outline: 2px solid var(--focus); outline-offset: 2px; }`.
Covers copy buttons and the scrollable `<pre>` regions (the only other
interactive controls on the page).

Prior finding, now fixed: `--focus` (and every other custom property) was
never defined — the stylesheet had `::root` instead of `:root` at line 3, a
typo that silently dropped the whole variable block, including the focus
outline color, code-block dark theme, and accent colors. Fixed to `:root`.
Re-verified: `document.styleSheets` shows the color scheme applied
(`--code-bg`, `--focus`, etc.) after the fix.

## 4. No console errors on load (part of criterion 6)

Check: `page.on('pageerror'|'console')`, load page, assert empty array.

```
node /tmp/a11y-check/clean.mjs
```

Result: `CLEAN CONSOLE ERRORS: []`. (A CORS/XHR warning appears only when
axe-core itself probes `style.css` under `file://` protocol during the
scan — that's axe's own stylesheet-parsing behavior, not a page bug; it
does not appear on a plain page load.)

## 5. Accessible names for copy buttons (screen-reader usability, WCAG 2.4.6 /
   best practice — not a stated numbered criterion, but blocks AT users)

Check: `document.querySelectorAll('.copy-btn')` → each button's `aria-label`.

Result: each of the 5 copy buttons has a distinct `aria-label` ("Copy
command for step N: <step title>") instead of all 5 sharing the bare name
"Copy", so a screen-reader user tabbing through buttons can tell them
apart.

## 6. Copy confirmation is announced (assistive-tech behavior)

Check: `aria-live="polite"` is present on each copy button in the static
HTML (not added dynamically after the text already changed, which several
screen readers miss). Text change to "Copied" is inside that live region
from the first click onward.

## 7. Color-scheme contrast — zero critical/serious in both light and dark,
   rest and .copied states (criterion 5 / 8)

Check: emulate `colorScheme: 'light'` and `'dark'` (page uses
`prefers-color-scheme`), scan with axe-core at page load (rest state) and
after clicking a copy button (`.copied` state) — 4 scans total.

```
node /tmp/a11y-check/four-scan.mjs
```

Result: all 4 combinations (light-rest, light-copied, dark-rest,
dark-copied) — `VIOLATIONS: 0`.

Prior finding, now fixed: `.copy-btn.copied` background `#2f8f4e` with
white text was 4.06:1 against WCAG's 4.5:1 text-contrast minimum — caught
only because this check scans the actual post-click DOM state, not just
rest. Only the rest-state axe scan had been run before this; the `.copied`
state (and dark mode after it landed) needed separate scans since axe
can't see a class that isn't applied yet. Fixed: background changed to
`#1f7a3d` (white text now 5.4:1). Re-verified clean in both color schemes.


## 8. Theme toggle — keyboard operability, focus indicator, axe-core clean in
   both explicit states (criterion 4 / 5)

Check: Tab to the toggle, confirm it's reachable and is the first stop;
press Enter, confirm `data-theme`/`aria-pressed`/visible label all flip;
read the actual computed `outline-style` when focused; run axe-core with
the toggle forced to each explicit state against the opposite OS
`prefers-color-scheme`, and re-run the earlier 4 light/dark × rest/copied
combos with the toggle present.

```
node /tmp/a11y-check/toggle-scan.mjs
```

Result: `#theme-toggle` is the first Tab stop (`<button>`, natively
focusable). Enter activates it → `data-theme="dark"`, `aria-pressed="true"`,
visible label updates to "Dark". Computed focus outline: `solid 2px
rgb(123, 168, 255)` (renders, not `none`). 6 axe-core scans — explicit
light (toggle forced light against OS dark), explicit dark (toggle forced
dark against OS light), and the original 4 combos re-run with the toggle
present — all `violations: 0`.

## 9. Print button — keyboard operability, focus indicator, print-media
   behavior (criterion 4 / 5)

Check: Tab twice (past the theme toggle) to reach `#print-btn`, read
computed focus outline; axe-core scan with the button present (screen
media); emulate `media: 'print'`, read computed `display` on
`.top-actions` and `.copy-btn`, axe-core scan under print media too.

```
node /tmp/a11y-check/print-scan.mjs
```

Result: `#print-btn` is the 2nd Tab stop (native `<button>`), computed
focus outline `solid 2px rgb(18, 88, 232)` (renders). axe: 0 violations
with the button present. Under emulated print media, `.top-actions` and
`.copy-btn` both compute to `display: none` (not just visually assumed —
read via `getComputedStyle`), and axe-core still reports 0 violations on
the print-media DOM.

## 10. Scrollspy TOC — keyboard order, focus indicator, non-color-only
   active state, axe-core clean, reduced-motion respected (criterion 4 / 5)

Check: Tab sequence through toggle → print → 8 TOC links; computed focus
outline on a link; computed `border-left`/`font-weight`/`aria-current` on
`.active` vs an inactive link (must differ by more than color/tint alone);
axe-core in light and dark; intercept `Element.prototype.scrollIntoView`
calls on TOC-link click under `reducedMotion: 'reduce'` vs
`'no-preference'` browser contexts, plus computed `scroll-behavior` on
`<html>`.

```
node /tmp/a11y-check/toc-scan.mjs
```

Result: Tab order is toggle → print → step 1 through step 8 links, in
order, matching visual/DOM order. Focus outline `solid 2px rgb(18, 88,
232)` renders. Active link differs from inactive by `border-left: 3px
solid rgb(181,101,29)` (vs transparent), `font-weight: 700` (vs 400), and
`aria-current="true"` (vs absent) — not color-only. axe-core: 0 violations
in both light and dark. Reduced motion: `scrollIntoView` called with
`{behavior: "auto"}` when `reducedMotion: 'reduce'`, `{behavior: "smooth"}`
otherwise; `<html>` computed `scroll-behavior` matches (`auto` vs
`smooth`) via the `@media (prefers-reduced-motion: no-preference)` guard
in `style.css`.
## Fixes applied directly (small, patched in place)

- `index.html`: added `tabindex="0"` to all 5 `<pre>` command blocks; added
  distinct `aria-label` and static `aria-live="polite"` to all 5 copy
  buttons.
- `app.js`: removed now-redundant dynamic `aria-live` attribute toggling
  (attribute is static in HTML).
- `style.css`: fixed `::root` → `:root` typo (was silently dropping every
  custom property, including the focus-outline color); added
  `pre:focus-visible` outline rule alongside the existing button/link rule;
  fixed `.copy-btn.copied` background `#2f8f4e` → `#1f7a3d` for 4.5:1+
  contrast with white text (was 4.06:1).
